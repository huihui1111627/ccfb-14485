# 主动测量地址定位（time-delay geolocation）

反电信诈骗研判要回答"这个地址大概在哪个城市"。买的商业地址库对**境外地址**和**机房/云主机**错得离谱
（真实案例：外省机房的地址被标成本市，抓捕组白跑一趟）。本项目用**主动时延测量**独立给出位置，
不信任任何地址库：

* 输出是**一个区域 + 置信度**，不是单一坐标 —— 便于研判人员按"区域内的城市"排序排查；
* 方法完全保守：只要测量正常，**真实位置一定在给出的区域内**；测量有问题时能指出是哪一条约束不可信并放宽；
* 附带一个可交互的地图页面，能看到每个探测点画的圆和最终区域。

互联网用**自写仿真**代替（`pygeoloc/sim.py`），仿真里显式建模了真实世界里让测量变脏的几种现象：
绕路（光纤不沿大圆走）、拥塞（重尾排队 + 少数目标持续拥塞）、不对称（去/回程路径与接入上下行不同）、
最后一跳接入时延、丢包。

> 本文所有数字都可由仓库内脚本复现，见"运行"与"结果"两节。

## 1. 原理

### 1.1 时延是距离的上界（第 1 条）

光在光纤里约 200 km/ms。测得 RTT 后，单程传播时延不可能超过 RTT/2，因此

    distance ≤ RTT/2 × v

每个探测点给出一个圆，**目标一定在所有圆的交集里**。这是本系统唯一的硬保证来源。
但直接用真空光速太松（实测中位数下圆半径是真实距离的 2~3 倍），交集经常退化成大洲尺度的宽条。

### 1.2 每个探测点自己的标定线（第 2 条）

每个探测点与**位置已知**的其他探测点互测 RTT，得到一批 (距离, RTT) 数据点，
拟合一条直线 `t = a + b·d`，并**强制压在全部数据点下方**（下包络）：

* 目标真实距离 `d` 满足 `b·d + a ≤ t`，所以反解 `R = (t − a)/b` 仍是**上界**；
* 但 `b` 比 `1/v_c` 大 2~3 倍（绕路 + 每跳处理），圆小了 2~3 倍；
* 数据点全部在线上方 → 不会因为标定太紧而把真值排除。

实现：`pygeoloc/calib.py`。斜率用"最贴近包络的那批点"稳健估计，再乘安全系数；
截距吸收不随距离增长的每跳开销，并额外留一段保守距离（`RTT_OVERHEAD_ABSORB_KM`）。

### 1.3 滤掉排队与处理，估计最后一跳（第 3 条）

* **排队**：每次测量都是重尾随机量，对同一 (探测点, 目标) 做多次 ping **取最小值**，
  排队时延被系统性滤掉（`Measurer.target_min`）。
* **每跳处理**：无法从单个 RTT 分离，被标定线的截距吸收。
* **最后一跳接入**：用 traceroute 找到路径上离目标最近的末跳路由器，
  `RTT_target − RTT_lastHop` 的差值里只剩接入链路 + 主机协议栈，
  再按真空光速换算成接入距离的**物理上界**——这是本系统收紧区域的第二个强约束。

### 1.4 交集为空时找不可信的测量（第 4 条）

测量异常（持续拥塞、路径异常、标定失效）会让某个圆偏小，交集变空。
`region.diagnose_and_relax` 用候选点投票：找"与最多约束同时相容"的点，
把仍然违背约束的那一条按**刚好容纳它所需的量**放宽 10%（而不是大放水），
必要时剔除最不可信的一条并记录诊断。地图页面上会显示哪条约束被放宽/剔除。

### 1.5 拓扑信息（第 5 条）

* **主机名**：`shl-cr2.isp-core...` / `cr3.hyderabad.example.net` 解析出 IATA 三字码或城市名
  （`topology.NameResolver`），给出 metro 级线索。主机名可能过时/张冠李戴，
  与测量冲突时自动忽略（冲突判定与忽略都会写进结果）。
* **递归测量**：路由器本身会回 ICMP。用**同一套"标定圆交集"方法**去定位路由器
  （`topology.RouterLocator`，结果带缓存，且有"路由器自身固定开销"的修正）。
* **目标在末跳附近**：末跳路由器已定位后，目标必在"路由器位置 ⊕ 接入距离上界"的圆内。
  这个圆通常只有几十~几千公里，但对"排除大洲尺度的错误"极有效。

### 1.6 先粗后精（第 6 条）

探测点不是越多越好：远处探测点的圆又大又容易被路径异常污染。
`planner.py`：先用几何上均匀散布的少量探测点（最远点采样）粗定位，
再围绕粗区域中心挑**附近**探测点精测（方向去重，保证基线张开），
远探测点只保留少量作为几何支撑。

### 1.7 区域 + 置信度（第 7 条）

交集区域的每个网格单元上计算

    后验 ∝ 人口密度先验 × 每个探测点的时延似然

* **人口先验**：城市人口核密度 + 陆地基础值（`region._population_prior`）；
* **时延似然**：`p(log(t / (a + b·d)))`，用标定残差的分布估计（`_logt_likelihood`）；
* 峰值/加权质心作为点估计，区域为**保守交集**（不是后验截断，因此覆盖率有保证）；
* 置信度 = 区域内后验质量 / 放宽 30% 后区域内后验质量（越"锐利"越接近 1）。

## 4. 验收指标（第 7 条）

`python tools/run_benchmark.py` 输出：

| 指标 | 说明 |
|---|---|
| 误差距离分布 | 点估计与真值的 haversine 距离：p50/p75/p90/p95/最大 + 各阈值命中率 |
| 覆盖率 | 真实位置落在给出区域内的比例 |
| 区域面积 | 中位数、分位数、几何均值 |
| 测量次数 | 每目标包数、traceroute 次数 |
| 点估计来源 | 后验峰 / 最近 RTT 探测点 (按区域尺度自动切换) |
| 基线对比 | ①最近探测点坐标 ②只用最近 K 个探测点的圆交集 ③真空光速圆 |
| 置信度校准 | 按置信度分箱的实际命中率 |

基线在 `evaluate.py` 中与主流程使用**同一批测量**（基线额外测量单独计数），
避免"基线测量更多所以更准"的偏差。

要点与**诚实的取舍**：

* **点估计**：中位 181 km（基线 295/378/463），p90 715 km（基线 756/1797/2180）——
  中位与尾部都更好。CDF 见 `out/figs/err_cdf.svg`。
* **区域**：中位 6.2×10⁵ km²（约一个中等省份）。
  纯圆交集基线的覆盖率略高（0.958 vs 0.933），但它们的区域大 3 倍；
  单位面积上的信息量本系统高一个量级。
  本系统优先保证"区域不要大得没法用"，同时把覆盖率守在 0.93 以上。
* **置信度校准**（`out/figs/calib.svg`）：高置信分箱（≥0.85，n=2019）实际命中 0.959，
  低置信（<0.3，n=234）0.850 —— 置信度有区分度，但不是完美校准
  （时延约束本身无法区分"近而慢"与"远而快"，见第 5 节）。
* **保守性旋钮**：`--conservatism 1.15` 的对照实验中覆盖率没有提升
  （0.940 vs 0.945），说明默认参数已在"覆盖率 / 面积"的拐点上。
* 基线使用**与主方法完全相同的测量**（同一批探测点、同样次数、同样取最小），
  只改变聚合方式；否则基线会因为"测得更少"而吃亏。

**分项（3000 目标）**

| 接入类型 | 占比 | 误差 p50 | 误差 p90 | 覆盖率 | 区域 p50 |
|---|---|---|---|---|---|
| fiber | 54% | 175 km | 586 km | 0.931 | 4.2×10⁵ km² |
| idc（机房） | 21% | 169 km | 560 km | 0.921 | 3.3×10⁵ km² |
| mobile | 13% | 183 km | 1135 km | 0.948 | 1.0×10⁷ km² |
| dsl | 10% | 234 km | 749 km | 0.962 | 2.8×10⁶ km² |
| satellite | 2% | 1249 km | 3078 km | 0.879 | 1.4×10⁸ km² |

| 区域规模 | 占比 | 误差 p50 | 误差 p90 | 覆盖率 |
|---|---|---|---|---|
| < 10⁵ km²（城市级） | 8.7% | 113 km | 450 km | 0.673 |
| 10⁵–10⁶ km²（省级） | 51.3% | 159 km | 396 km | 0.958 |
| 10⁶–10⁷ km²（几个省） | 26.2% | 287 km | 826 km | 0.968 |
| > 10⁷ km²（大洲级） | 13.9% | 350 km | 2381 km | 0.938 |

城市级区域（8.7%）的覆盖率只有 0.673 —— 这里有个**真实的两难**：
这些目标的圆交集本来就很小（<10 万 km²），说明各探测点的测量高度一致；
但一旦其中某条测量因为持续拥塞偏小，交集会被"锁死"在错误的小块里，而
圆交集本身无法自查。**这类结果最需要人工复核**（页面上的置信度会偏低）。

**"不知道"也必须是答案**：13.9% 的目标区域达到大洲级（卫星接入、持续拥塞、
远距离机房），此时系统给出的是"大区域 + 低置信"，而不是编一个城市。

区域越大，点估计越难做（这是上界约束的固有性质，见第 5 节）。
因此点估计按区域尺度切换（`LocateConfig` / `LocateResult.point_src`）：

* 区域等效半径 ≤ 550 km：取**后验最大单元**（人口 × 时延最相容处）；
* 更大：取**实测 RTT 最小的探测点**（物理上离目标最近；后验峰在大区域里
  容易被邻近大城市吸走）。

同一批测量的对照实验中，这个切换把 p90 从 1117 km 降到 835 km。

## 5. 已知局限（会影响研判，必须知道）

1. **只有上界，没有下界**。圆交集只能排除"太远"，不能排除"太近"。若目标是低时延接入（FTTH/机房），
   而交集中有多个相距很远的城市，单靠时延无法区分 —— 这时需要人口先验与拓扑约束，且置信度会相应降低。
2. **持续拥塞不可滤**。少数目标全天拥塞（仿真中 7%），多次取最小也滤不掉，圆会虚大（保守，不会排除真值）。
   卫星接入（2%）的固定时延极大，区域会很宽 —— 这是物理决定的，不是算法缺陷。
3. **标定依赖探测点网络质量**。若某探测点的标定数据很少，会退化为真空光速；置信度会体现这一点。
4. **主机名不可全信**（仿真中 8% 的路由器主机名指向别处）。系统只把主机名当弱先验，
   与测量冲突时自动忽略并记录。
5. **人口先验只影响后验/点估计，不影响区域**。若某个低人口机房的地址很重要，
   不允许因为人口先验把区域裁掉（这正是"对外省机房标成本市"这类错误的来源）。

## 6. 与"只用最近探测点"的区别

在**同样的测量**下（同一批探测点、同样次数），"最近探测点当答案"的 p50 是 308 km、
p90 781 km；本系统 183 / 719 km。更重要的是，最近探测点这种做法：

* 没有**区域**，无法表达"我有多确定"；
* 没有**置信度**，没法按可信度排序；
* 一旦最近的探测点落在错误的城市（路径异常/坐标错），答案直接错到另一个城市；
* 无法处理"目标在机房、接入点离真实位置很远"的情况。

本系统的价值在于：**保守区域 + 可解释的约束 + 何时不可信的诊断**。
